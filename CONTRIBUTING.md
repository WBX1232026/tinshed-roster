# Contributing to Tinshed Roster

## Branch naming

Each user story gets its own branch:

- `feature/<story-name>` — new feature
- `fix/<bug-name>` — bug fix
- `docs/<topic>` — documentation

Examples:
- `feature/volunteer-create`
- `feature/performance-create`
- `feature/assignment-create`
- `feature/one-role-rule`
- `feature/roster-gap-view`

## Workflow

1. Create a branch from `main`.
2. Write code and tests.
3. Commit with a clear message.
4. Push the branch to GitHub.
5. Open a Pull Request.
6. Request review from at least one other team member.
7. Address review comments.
8. Merge into `main` after approval.

## Commit messages

Use clear, present-tense messages:

- `Add volunteer creation feature`
- `Fix one-role rule rejection message`
- `Update README with setup instructions`

## Definition of Done

Every story must meet the Definition of Done in the README before merging.
